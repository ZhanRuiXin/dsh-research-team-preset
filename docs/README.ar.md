## نظرة عامة

Research Team Mode هو إعداد وكيل DSH يحوّل جلسة واحدة إلى فريق بحث صغير ومنسّق. يتولى القائد (Lead) تخطيط العمل وإدارة لوحة المهام وتوزيع البطاقات ودمج النتائج والتواصل مع المستخدم. وتغطي ستة أدوار افتراضية الاستشارة العلمية، والأدبيات والأدلة، والشفرة، والتشغيل، والمراجعة المستقلة، وكتابة الورقة.

الوضع مناسب للبحوث التي تمتد أيامًا أو أسابيع، وتحتاج إلى أدلة قابلة للتتبع وحدود واضحة بين الأدوار. وهو ليس وضع أسئلة سريعة أو تعديلات صغيرة لمرة واحدة.

## لمن

- المشاريع البحثية التي تجمع مراجعة الأدبيات والتنفيذ والتجارب وإنتاج الورقة.
- الفرق التي تريد ربط كل ادعاء بمصدر أو سجل تشغيل أو سجل تجربة.
- المستخدمون الذين يفضلون مستشارًا ومراجعًا مستقلًا بدل وكيل عام واحد.
- الأعمال التي يجب أن يبقى القرار النهائي فيها للمستخدم.

## المزايا

- **ستة أدوار افتراضية**: advisor (مستشار علمي)، researcher (الأدبيات والأدلة)، builder (الشفرة)، runner (التدريب والتشغيل)، reviewer (المراجعة)، writer (كتابة الورقة).
- **لوحة المهام أولًا**: ينشئ القائد البطاقات، ويتولى الأعضاء تنفيذها، ويرسلون تقرير تنفيذ، ثم يراجعها reviewer بشكل مستقل.
- **نموذج لكل دور**: تتيح صفحة إعدادات الإضافة اختيار provider وmodel وقوة الاستدلال لكل عضو.
- **الإنجاز للمستخدم فقط**: يصل الوكيل إلى `in_review`، ولا ينقل البطاقة إلى `done` إلا المستخدم من الواجهة.
- **بيئة PTC**: يجمع `run_code` وSDK المولّد العمليات الدفعية ويقلل جولات الذهاب والإياب.
- **قابلية التتبع**: تبقى الأدلة وسجلات التشغيل والقرارات في تعليقات بطاقات المهام.

## البدء السريع

1. في ملف DSH نفسه، فعّل Agent Teams (`@deepseek-ai/dsh-experimental-agent-team-profile`) و`dsh-taskboard`.
2. ثبّت هذا الـ bundle عبر مسار محلي أو `link:`، ثم أعد تشغيل DSH.
3. افتح جلسة جديدة واختر «Research Team Mode»؛ واستخدم `presetId=research-team` في بطاقات المهام.
4. من «Plugins → @local/dsh-research-team-preset → research-team-settings → Configure» اضبط النماذج الافتراضية.
